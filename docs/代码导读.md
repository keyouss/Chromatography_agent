更新时间：2026-10-03  
学习对象：D:\Jupyter\Chromatography_agent 当前工作树  
标准：start-study 的 codebase 源码学习专项与源码阶段教学文件

这份材料围绕一次真实用户行为组织：用户从 Vue 页面或助手提交色谱预测，API 校验并持久化任务，Outbox 把任务交给 Worker，Worker 重新加载快照并调用真实科学适配器，前端再查询结果或接收助手事件。

证据标记：已确认=直接读到定义、调用点、配置或测试；推断=由多个源码位置拼出的合理解释；未验证=尚无真实 Windows 服务、MySQL、Redis、Worker、浏览器或 Provider HTTP 证据。

## 1. 先形成这个心智模型

**API 不执行模型，只创建可恢复的业务任务；Worker 才执行模型。**

~~~text
Vue / 助手
  → /api/v1
  → FastAPI create_app()
  → prediction.router.create_router()
  → PredictionCreateService.create()
  → SQLAlchemyPredictionPersistence.create()
  → Job + JobAttempt + OutboxEvent
  → OutboxDispatcher / Redis / Worker
  → PredictionProductionWorker.handle()
  → registry.execute_snapshot()
  → finish() 写回 Job/Attempt/PredictionRow
  → 前端轮询、助手事件或结果卡片
~~~

目录职责：

~~~text
frontend/src/modules/prediction   页面、Pinia 状态、统一客户端
frontend/src/modules/assistant    会话、Run、工具调用、SSE 恢复
backend/src/chrom_platform/app.py 应用组装和请求级依赖
backend/.../modules/prediction    DTO、路由、服务、持久化、Worker
backend/.../modules/assistant      摘要、模型草稿、Provider、助手工具
backend/.../task_core             Job、Attempt、Outbox、Confirmation
backend/.../assembly              按 manifest 装配运行包
backend/alembic                   数据库迁移
builds/                           profile 能力声明
~~~

Pydantic DTO 是跨边界数据形状；Outbox 是事务内记录的待投递事件；attempt 是一次执行代次；dispatch_id 是一次投递标识；lease/fencing 防止旧 Worker 覆盖新状态。

async function loadRun(id: string) {
  await Promise.all([getRun(id), listEvents(id), listToolCalls(id)])
  if (run.value && !TERMINAL_RUNS.has(run.value.status)) startEventStream(id)

function startEventStream(id: string) {
  stopEventStream()
  stream = createEventStream("/agent-runs/" + encodeURIComponent(id) + "/events/stream", {
    afterSeq: lastEventSeq.value || undefined,
    lastEventId: lastEventSeq.value || undefined,

}

## 4. 当前四类问题对应的代码

### 4.1 批量 Worker 补丁被审批拒绝

相关文件：backend/src/chrom_platform/modules/prediction/batch_worker.py、backend/src/chrom_platform/worker_cli.py、backend/src/chrom_platform/assembly/prediction_worker.py。

BatchPredictionWorker.execute() 是同步 Session 核心；BatchPredictionProductionWorker 缺少完整异步 handle、execute、cancel，也没有注册进 worker_cli 的生产选路。worker_cli 的 _WORKER_CLASSES 没有 batch 类，_WORKER_JOB_KINDS["prediction"] 只有 prediction。ProfileWorkerPlan.from_manifest() 虽可把 batch_prediction 加入 allowed kind，build_worker_routes() 仍只创建 PredictionProductionWorker。_RESOURCE_TYPES 认识 batch_prediction，但资源类型表不是 handler registry。

被拒补丁涉及 lease、attempt、Outbox、取消和终态 fencing/CAS，因此自动审批把它视为可能改变生产状态的高风险代码。用户已授权；拒绝发生在代码写入阶段，未接触真实 DB/Redis，也未绕过。

### 4.2 profile 裁剪混入 batch 迁移或过期派生物

相关文件：builds/manifest.py、builds/universal-v1.json、backend/src/chrom_platform/assembly/profile.py、backend/alembic/versions/0011_m2_batch_prediction.py、backend/tests/test_worker_migration_topology.py。

builds/manifest.py 的 TOOLS 是允许值 catalog；具体 profile 的 prediction_tools 才是实际声明。assemble_profile() 计算 batch_enabled，删除 batch 源文件和 M2 wiring，并调用 _profile_migrations()。

_profile_migrations() 按 down_revision 闭包选择迁移；0011_m2_batch_prediction.py 的 parent 是 0010_model_center_job_fencing。如果使用旧 manifest 生成，或只修源码而不重新生成 backend/.generated/profile-packages、frontend/build-output/independent-check，就会出现“源码没有 batch、迁移/派生 manifest 仍有 batch”。

测试同时要求主仓库识别 0011，又要求无 batch profile 物理不含它；这是候选源和裁剪交付包两个层次。最新 testing/STATUS.md 记录静态裁剪证据，同时明确正式 batch handler、真实 DB/API/Worker/browser 仍未完成。

### 4.3 Docker、MySQL、Redis 使真实 E2E 阻塞

deploy/v1/run-local.ps1 只从受保护 runtime.json 读取数据库、Redis、端口和 ready file。当前已确认 Docker daemon 不可用，既有 MySQL/Redis 容器未运行，3306/6379/9012/5173 无监听。路由/OpenAPI/组件通过不能替代浏览器→API→DB→Redis→Worker→模型的证据。服务停止时没有 ready marker 属预期状态。

### 4.4 Provider 探针被审批阻塞

priority.py 的 _resolve_key_reference()、resolve_runtime_config()、inspect_provider_config() 与 deploy/v1/dpapi-secret-source.ps1 形成 DPAPI 文件 → 进程 API_KEY → resolver → Provider 的路径。runtime JSON 只放 key reference 和 secret source path；前端不接触密钥。

配置解析、脱敏和密钥引用安全已确认；用户授权的合成只读 Provider 探针仍在执行审批阶段被拒，尚未解密、联网或取得 HTTP 响应。因此配置 READY 不能写成 Provider 调用成功。
